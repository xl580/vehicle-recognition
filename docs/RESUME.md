# 简历写法与面试要点

> 这个项目在简历上的价值 = 可量化的指标 + 完整的工程链路 + 你能讲清楚的技术取舍。
> 以下数字均为实测真实结果，测试细节见 docs/DESIGN.md 与 docs/realworld_eval.md。

## 一、简历项目条目（推荐版）

**车辆识别系统 · 车牌 / 品牌 / 车型 / 视频（个人项目）**
`Python` `PyTorch` `YOLOv8` `ResNet50` `CLIP` `HyperLPR3` `FastAPI` `SQLite`

- 设计并实现端到端车辆识别流水线：车辆检测 → 车牌检测/识别 + 品牌/车型双模型分类，单图输出车牌号、车牌类型、品牌、车型、颜色及各阶段置信度；**支持图片与视频双入口**
- 基于 **CCPD（9,833 张）微调 YOLOv8n** 车牌检测，**mAP@0.5 = 0.9949**（P/R ≈ 99.9%）；配合 HyperLPR3 完成含警牌/新能源绿牌在内的中文车牌识别，真实照片实测 3/3
- 基于 **Stanford Cars（185 类）微调 ResNet50**，车型细粒度分类 **Top-1 90.10% / Top-5 98.31%**；采用 RandAugment + 随机擦除、骨干低学习率微调策略
- **发现并解决跨域失效问题**：棚拍数据导致模型学到背景捷径，真实街拍品牌识别仅 33%；引入 **CLIP 视觉特征 + 线性探针**做品牌判别，并用**品牌约束解码**融合双模型，置信度从 0.2 提升至 0.95+，跨域准确率提升至 42%（自建 12 品牌实拍测试集）
- 实现**视频流识别管道**：定时抽帧（2 FPS）+ 暗帧过滤 + 帧数上限控制，按车牌号跨帧聚合去重（保留最高置信度结果），车型/品牌采用多数投票；9 秒 225 帧实测视频抽 19 帧即可稳定识别 2 个车牌，耗时 5.9s
- 设计**识别记录持久化方案**：SQLite 存储识别结果（来源/耗时/各阶段结果），结果图落盘静态服务；配套 REST 查询/删除接口与前端记录页（来源筛选、缩略图预览、单条删除/清空）
- 端到端 GPU 推理 **86.6ms/张 ≈ 11.5 FPS**（较 CPU 加速 **4.7×**）；FastAPI 封装五接口 + 带标注框结果图 + 前端演示页，模块级自动降级设计保证部分依赖缺失仍可运行

## 二、如果简历空间只有一行

> 基于 YOLOv8 + ResNet50 + CLIP 实现车牌/品牌/车型识别（车牌 mAP 0.995、车型 Top-1 90.1%），支持图片与视频识别（抽帧去重 + 跨帧聚合），GPU 端到端 87ms/图，FastAPI + SQLite 完成服务化与记录持久化。

## 三、面试必问 & 答题要点

| 问题 | 回答骨架 |
|---|---|
| 为什么分两级检测，不直接端到端？ | 车牌是小目标且尺度差异大，先整图定位再裁剪送 OCR 显著提升识别率；分模块便于单独迭代替换 |
| 品牌/车型怎么做的？ | **双模型**：ResNet50 在 Stanford Cars 上微调做 185 类细粒度车型（Top-1 90.1%）；品牌用 CLIP 特征 + 线性探针（域内 83.7%）。推理时先 CLIP 判品牌，再对 ResNet50 做**品牌约束解码**（只在该品牌类别里取 argmax），品牌不在车型模型词表时自动退回 |
| 你遇到的最大的坑是什么？ | **跨域失效**：Stanford Cars 全是棚拍图，ResNet50 验证集 90% 但街拍只 33%——模型学了背景捷径。排查过程：先用验证集复核排除预处理 bug（期间发现 BGR/RGB 通道错位），再用自建 Wikimedia 实拍集定位到域偏移。解法是 CLIP 特征（4 亿图文对预训练，跨域鲁棒）+ 整图/裁剪双视图特征平均 |
| 为什么不全用 CLIP？ | CLIP 零样本对细粒度车型几乎无区分力（56% 品牌级已是上限），而 ResNet50 微调在域内 90%+。两者互补：CLIP 管泛化，ResNet50 管细粒度 |
| 指标可信吗？有没有泄漏？ | 指标分两层报：域内（Stanford val 768 张）和跨域（自建 12 品牌实拍集）。明确指出 Stanford 官方划分存在同车多图泄漏，所以 val 90.1% 是偏乐观的上界——这个 caveat 本身就是加分点 |
| 视频识别怎么设计的？为什么不用逐帧全跑？ | 逐帧全跑浪费且相邻帧高度冗余。方案：**定时抽帧（2 FPS）**降低计算量 + 暗帧过滤避免无效推理 + max_frames 上限防超长视频；结果层面按车牌号跨帧**聚合去重**（同车牌只留最高置信度），车型/品牌用多数投票抗单帧抖动。权衡点：抽帧间隔是精度/速度旋钮，帧太密会重复计算，太疏会漏短暂入镜车辆 |
| 车牌去重为什么用置信度最高的那帧而不是多数投票？ | 车牌号是离散文本，错一个字符就是完全错误的结果，没有"少数服从多数"的平滑空间——目标是找到**成像质量最好**的那一帧（距离近、角度正、无遮挡），最高置信度正是质量代理；车型/品牌是分类任务且逐帧独立，才适合投票 |
| 记录功能怎么做的？为什么选 SQLite？ | 结果（来源/耗时/结构化字段）+ 标注图落盘，SQLite 单文件零运维，符合个人项目量级；接口层做了查询/来源筛选/单条删除/清空，前端用缩略图直读静态目录而非存 base64——面试可主动讲"什么量级该换 PostgreSQL" |
| 训练细节 | 185 类、7,376 训练/768 验证；AdamW（骨干 0.1× 学习率）+ Cosine 退火 + Label Smoothing 0.1 + RandAugment/RandomErasing；RTX 3050 Ti 4GB 上 bs=8、AMP 混合精度，15 epoch 约 22 分钟 |
| 怎么优化推理速度？ | 模型换小（yolov8n）、显式指定 GPU 设备（ultralytics 默认 CPU 的坑）、后续可 ONNX/TensorRT + FP16 |
| badcase 怎么分析？ | docs/realworld_eval.md 逐张记录预测与真值；错误集中在：中国特供车型（不在美系词表）、同集团品牌（Honda→Acura）、老款车型（Stanford 只覆盖 1991-2012） |

## 四、加分项（本项目已做到）

1. **消融对比**：ResNet50 端到端微调 vs CLIP 线性探针，域内/跨域双指标对比表
2. **跨域评估集**：自建 Wikimedia 实拍 12 品牌测试集 + 自动化评估脚本 + 报告
3. **性能报告**：GPU/CPU 各阶段耗时（检测 28ms / OCR 为主瓶颈 / 分类 ~15ms）
4. **工程素养**：类型注解、docstring、模块级降级、pytest、断点续传下载脚本
5. **完整产品闭环**：视频/图片双入口 → 识别 → 持久化 → 前端可视化记录管理，能演示真实使用场景而非只有 demo 脚本

## 五、避坑提醒

- 只调 API 不训练 → 面试一问「你训了什么」就露馅；本项目车牌检测和车型分类均为自训
- 指标不要编，面试官会追问测试集划分与泄漏；主动讲出「同车多图泄漏」问题反而加分
- 不要写「准确率 99%」却说不清是哪个指标、在哪个数据集上；每个数字都要能指到 docs/ 里的报告
